# CQRS / MediatR 面试题（25）

* * *

## 1\. What is CQRS and why do we use it?

考察点：是否理解读写分离本质

标准答案：  
CQRS = Command Query Responsibility Segregation，把读和写分离成不同模型。

深度要点：

  * Write Model：强一致 + domain rules

  * Read Model：优化查询 + denormalized

  * 独立扩展

常见错误：

  * 认为只是“分两个 service”

Follow-up：  
什么时候 CQRS 是 overengineering？

* * *

## 2\. CQRS solves what problems in traditional CRUD systems?

考察点：痛点理解

答案：

  * 复杂 domain model 被 query 拉垮

  * 读写竞争资源

  * SQL join performance bottleneck

  * scaling read/write together

* * *

## 3\. When NOT to use CQRS?

考察点：trade-off

答案：

  * CRUD简单系统

  * low scale system

  * strong transactional consistency required

  * team maturity low

* * *

## 4\. Difference between CQRS and simple layered architecture?

答案：  
CQRS separates models, not just layers.

Layered:

  * same model used for read/write

CQRS:

  * separate models + potentially separate storage

* * *

## 5\. What is MediatR and why use it?

考察点：.NET architecture understanding

答案：  
MediatR implements mediator pattern:

  * decouples request sender and handler

Benefits:

  * cleaner controllers

  * separation of concerns

  * pipeline behaviors

* * *

## 6\. MediatR vs direct service call?

答案：  
Direct call:

  * tight coupling

MediatR:

  * decoupled

  * easier cross-cutting concerns

Trade-off:

  * harder debugging

  * indirection overhead

* * *

## 7\. What are Commands and Queries in CQRS?

答案：  
Command:

  * changes state

  * returns void or ID

Query:

  * returns data

  * no side effects

* * *

## 8\. Can queries modify state?

答案：  
No. Violates CQRS principle.

But in real systems:

  * logging may occur

  * caching updates possible (edge case)

* * *

## 9\. How does MediatR pipeline behavior work?

答案：  
Middleware-like pipeline:

    Request → Behavior1 → Behavior2 → Handler → Response

Used for:

  * logging

  * validation

  * caching

  * authorization

* * *

## 10\. How do you implement validation in MediatR?

答案：  
Using pipeline behavior:

  * FluentValidation

  * ValidationBehavior<T>

* * *

## 11\. CQRS and Event Sourcing relationship?

答案：  
CQRS ≠ Event Sourcing

But often combined:

  * CQRS: structure

  * Event sourcing: storage

* * *

## 12\. What is eventual consistency in CQRS?

答案：  
Read model may lag behind write model due to async projection.

* * *

## 13\. How do you build read models in CQRS?

答案：

  * projection from events

  * ETL from write DB

  * materialized views

* * *

## 14\. What are risks of CQRS?

答案：

  * complexity

  * eventual consistency bugs

  * debugging difficulty

  * data duplication

* * *

## 15\. How do you handle transactions in CQRS?

答案：

  * write side transactional

  * read side eventual consistency

  * saga if cross-service

* * *

## 16\. CQRS in microservices?

答案：  
Each service may have:

  * own command model

  * own query model

* * *

## 17\. How does MediatR support Clean Architecture?

答案：

  * Application layer uses MediatR

  * Domain is isolated

  * Infrastructure decoupled

* * *

## 18\. How do you test MediatR handlers?

答案：  
Unit test handler directly:

  * mock dependencies

  * call handler.Handle()

* * *

## 19\. What is the performance overhead of MediatR?

答案：

  * reflection-based dispatch

  * negligible for most systems

  * pipeline adds small latency

* * *

## 20\. Can MediatR replace controllers?

答案：  
No.

Controller:

  * HTTP concerns

MediatR:

  * application logic

* * *

## 21\. How do you implement caching with MediatR?

答案：  
Pipeline behavior:

  * check cache before handler

  * store result after execution

* * *

## 22\. How do you handle idempotency in commands?

答案：

  * idempotency key

  * dedup table

  * event store uniqueness

* * *

## 23\. CQRS + DDD relationship?

答案：  
CQRS fits well with DDD:

  * command = aggregate behavior

  * query = read model

* * *

## 24\. What are typical CQRS anti-patterns?

答案：

  * over-splitting services

  * unnecessary event sourcing

  * too many small commands

  * mixing query/write models

* * *

## 25\. Design a CQRS system for banking transfer

答案：

Write side:

  * TransferCommand

  * validate balance

  * update accounts

Read side:

  * transaction history table

  * account balance projection

Event:

  * MoneyTransferredEvent

Consistency:

  * eventual consistency for reporting

  * strong consistency for transfer execution
